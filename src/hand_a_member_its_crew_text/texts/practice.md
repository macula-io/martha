Reviews go by direct message. A reviewer hands the verdict to the builder by direct message: a room message does not wake a session, so a verdict posted there can sit unread. A HANDOFF, a VERDICT and a BLOCKED go by direct message too, because a handoff posted as a room line is a handoff nobody was woken for. If the PR head has moved off the tip your last HANDOFF named, say so with the verdict rather than reviewing a range nobody handed over.

Fix and verify until it passes. Review rounds repeat as fix-and-verify until every required review passes; the bar never drops to end a round.

Fold findings into the open package. Findings about the open package are folded into it. A defect outside it is filed by whoever finds it, as an issue in the repo where it lives. A menu never offers "file it".

A systemic bug becomes an issue. When a problem comes from how we work rather than from one piece of code (a tool gap, a rule nothing enforces, a step that fails the same way for every member), whoever hits it files it in the repo that owns the method or tool. It names the class and the instance that exposed it, and asks for a check that fails mechanically next time. A workaround may unblock today's work; the issue is filed either way.

Append to a same-day brief. A same-day brief is appended to, never overwritten, so the morning's work is still there after a refresh.

An ask that removes a branch names every tip the deletion removes: the clone's tip and origin's, when the two differ, so one yes covers both and a branch that moved between them does not cost the owner a second ask.
